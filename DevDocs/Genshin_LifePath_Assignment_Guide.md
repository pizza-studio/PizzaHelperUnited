# 原神角色命途歸類準則

> 最後更新：2026年9月21日
> 對應資料：`Packages/EnkaKit/Sources/EnkaKit/Assets/GenshinLifePathMap.json`（2026-09-21 計 148 筆）

原神本身沒有「命途」系統。這份對應純屬**非官方詮釋**，存在的原因是面板系統與星穹鐵道共用：原神角色必須有一個命途值，才能讓面板與證件照在美術上與星鐵角色對齊，同時讓玩家一眼看懂該角色在隊伍中的主要職能（見 Release Notes 5.3.1）。

---

## 1. 用途與定位

- 沒被指定的角色一律落到 `Enka.LifePath.none`；`AvatarSummarized_GIInits.swift` 的註解講得很直白：「原神角色没有命途的概念。」
- 命途值影響兩處 UI：角色面板（`AvatarSummarized_GIInits.swift`）與角色肖像圖騰（`CharacterIconView.swift`）；圖示資產名為 `path_<命途>`（`Enka.LifePath.iconAssetName`）。
- 因為這是「一眼懂」的標籤，判準只能是**招牌職能**，不是機制清單、也不是機制純度測試。

## 2. 檔案與技術約定

- 這份 JSON 是**手動維護**的，沒有任何產生器會寫出它；EnkaDBGenerator／GachaMetaGenerator 的產線都不涉及此檔。
- 格式：`[{ "id": "<avatar ID 字串>", "path": "<命途>" }]`。
- `path` 只能是 `Enka.LifePath` 的 **case 名稱**：`Destruction`、`Hunt`、`Erudition`、`Harmony`、`Nihility`、`Preservation`、`Abundance`、`Remembrance`、`Elation`。
  - ⚠️ **不可**寫 enum 的 rawValue（`Warrior`／`Shaman`／`Rogue`／`Mage` 等）。解碼器先用 case 名稱比對，失敗才退回 rawValue；**任何一條目解碼失敗，整份 `allMap` 會靜默變成空字典**，全 App 的命途圖示一起消失。
  - 排查線索：解碼失敗時 `LifePath.swift` 會記一行 `EnkaKit: Cannot access RealNameDict.json.`——該訊息是複製貼上的筆誤，實際上指的是 `GenshinLifePathMap.json`。
- 追加角色時，把條目插在 **ID 遞增**的位置，維持整份檔案排序。
- 有變體的角色要逐項列出：旅行者（`10000005-5xx`／`10000007-7xx`）、奇偶（`10000117-1170x`／`10000118-1180x`）。
- `guessPath(for:)` 依序以 ID 的前 14／12／8 碼回退比對，所以一般角色的後綴變體（例：`10000143-14302`）不需要另列，會自動命中 `10000143` 那一筆。

## 3. 判準（依序套用）

命途＝該角色的**招牌職能**：玩家會怎麼跟你介紹這個角色，那就是他的命途。

1. **職能大類**：坦克／護盾 → 存護；純治療 → 豐饒；**有隨行召喚物（drone）輔助攻擊的角色，預設先考慮記憶**；隨機／劇場 → 歡愉（現有兩例：芙寧娜＝演出主題；奇偶＝技能附帶的隨機性）。
   - 記憶的例外：若該角色自身的機制特性放大了其與其他命途的重疊度，則依該重疊判，並逐案登錄（見第 5 節「記憶（drone）的預設與例外」）。
2. **輔助細分**：招牌是「為我方增益」→ 同諧；招牌是「為敵方減抗／掛狀態」→ 虛無；兩者兼具時，看哪一臂是「非帶他不可」的理由。
3. **輸出細分**：站場循環（有代價或有資源機制）→ 毀滅；單體定點 → 巡獵；範圍法核 → 智識。
4. **例外（Acheron 條款）**：主C 的循環若由「隊友／敵方共同施加的反應、狀態、層數」餵養，且該體系本身屬減益／反應體系，可歸虛無。

### 已否決的規則

- **「凡有抗性削減者一律歸虛無」——不成立。** 原神的減抗來源包含聖遺物套裝（翠綠之影等）、武器、命座與隊友；照這條規則，鍾離（玉璋護盾的 A4）、辛焱（技能附帶物理減抗）、麗莎（A4 降防）都得搬進虛無。減抗只在「該角色的招牌就是減抗／掛狀態」時才是虛無的依據。
- **不要把原神機制硬套星鐵標籤。** 星鐵自身也不按機制純度分類：Acheron 是虛無命途的主輸出；Aventurine 是存護命途卻會給敵人掛易傷（Unnerved）。兩邊機制並非一一對應。
- **星鐵對照的時序陷阱（2026-09-21 補記）。** 引用星鐵角色當旁證前先核實裝日：記憶命途 2025-01-15（3.0）才隨憶靈系統上線（同日實裝 Trailblazer·記憶「迷迷」；Aglaea 於 2025-02-05 上線，是第一位記憶五星）。Lingsha（2024-10-02，豐饒）下池時記憶命途尚不存在，故不能拿她證明「治療＋召喚物≠記憶」。星鐵的記憶是**憶靈機制桶**（見第 5 節），不是「有召喚物」桶。

## 5. 判例與理由

### 需要特別記住的判例

**茲白 → 虛無（2026-01-10，Acheron 條款）**

- 理由：她的「時隙浮光」由自身攻擊 ＋ **隊友觸發月結晶反應**餵養（「月兆·滿輝」：隊友觸發月結晶為她累積 35 點），滿層後消費施放「靈駒飛踏」；同時她提升**我方**月結晶反應基礎傷害 14%（C2 再 +30%）並使隊伍月兆等級 +1。＝「隊伍餵層的堆疊型主C」，比照星鐵 Acheron。
- ⚠️ 不要把理由寫成「月結晶＝對敵易傷／DoT」。遊戲文本寫的是「提升**隊伍中角色**造成的月結晶反應的基礎傷害」（我方增傷），而月結晶反應本身是「在目標附近生成三枚月籠」、由月籠發動攻擊。

**芙寧娜 → 歡愉（2026-01-10 改判；原值：記憶）**

- 她的增益投遞方式其實是「對我方」：爆發「萬眾狂歡」把「氣氛值」轉化為隊伍增傷與受治療加成，而氣氛值由全隊的生命值變動累積；元素戰技「孤心沙龍」召喚的「沙龍成員」／「眾水的歌者」則是召喚物（傷害／治療兩套陣容，可切換）。
- 依第 2、1 條，職能判準會給「同諧」（我方增益）或「記憶」（召喚物，即改判前的值）。改判為「歡愉」屬**主題優先**：角色 fantasy 本身就是舞臺／歌劇院／演出（「氣氛值」＝全隊拿生命值換來的演出，再由演出換得全隊增益）。
- 她是全檔唯一的歡愉條目；星鐵側的歡愉命途角色則是 v4.0 才出現——星鐵第一個歡愉角色是火花（Hibana；英文版名 Sparxie）；星鐵 2.0 的花火（Hanabi；英文版名 Sparkle）是另一名角色，兩者在 4.0 主線劇情之後合而為一（見 The Latte Helper Release Notes 5.7.5 的「《星穹鐵道》v4.0 的新角色（爻光、火花）」）。
- 註：本條是「記憶的例外」的首例，已定案（維護者 2026-09-21）。她有 drone（沙龍成員／眾水的歌者），依預設本應先考慮記憶，但其機制特性（全隊生命值換來的全隊增傷＋受治療加成）與演出主題使與歡愉的重疊度更高。下一個維護者請勿照第 2 條把她改回同諧。

**琺露珊 → 同諧**

- 招牌是為風系主C 提供增益：風元素傷害加成 32.4%（Q Lv.10）、烈風護持（A4：處於「祈風之賜」的角色造成風傷時，依她基礎攻擊力的 32% 追加傷害）、C6 風傷暴擊傷害 +40%。
- 她的「詭風之禍」對敵減抗 30% 只是同一發烈風波的配套。「增益為主、減抗為輔」的輔助一律判同諧（同型：申鶴、尼可、希諾寧）。

**沃雅妮莎 → 同諧（2026-09-21）**

- 與同批的 Alyosha（`10000148`）同型：治療當前場上角色 ＋ 反應體系啟用 ＋ 反應傷害增益；亦比照希諾寧（減抗＋治療的五星期輔助）。
- 其水／冰抗 −30%（技能 Lv.10；Lv.1 為 16.5%）與風抗 −35%（A4）屬配套減抗；治療、抗打斷、領唱／重唱增傷才是她進隊的理由。
- 同日曾一度依「有減抗即虛無」改判為虛無，該規則撤回後還原為同諧。
- 註：她同樣有 drone（喚春角笛），屬「記憶的例外」——見下節。
- 2026-09-21 複核：以星鐵 Hyacine（記憶）對照後，維護者裁示維持同諧（「先不變」）；理由見下節「星鐵側的參照」——Hyacine 的記憶來自憶靈系統，不構成「治療＋召喚物 → 記憶」的通則。

**奇偶（Manekin／Manekina）→ 歡愉（2026-09-21 改判；原值：毀滅）**

- 14 筆＝ 7 元素（火／水／風／冰／岩／雷／草）× 2 性別（`10000117-1170x`、`10000118-1180x`）；男性與女性版本的六個技能名稱與說明逐條相同，所以判一次即可。5★ 單手劍、攻擊力% 成長、**沒有命之座**；設定是「筆名歐科塔維亞的魔女託付給你和派蒙的人偶」，用於探索「千星奇域」。
- kit：戰技「戒懲轟擊」＝自身元素範圍傷害＋後撤，之後普攻／重擊／下落轉為不可被附魔覆蓋的自身元素傷害（2 次可用次數）；爆發「禁入限區」＝召喚跟隨自身的「禁限區域」持續傷害，敵人踏入再吃一次（0.5 秒間隔）；A1「戰域重劃」離場時禁限區域爆炸（200% 攻擊力）；A2「交戰持備」後台低能量回能；A3「靈巧戰姿」施放戰技／爆發時**從已存裝扮方案中隨機挑一套切換**。
- 判為歡愉的理由：**全遊戲唯一真正帶「隨機」的機制**（靈巧戰姿）；其餘部分其實是教科書式的站場附魔劍 DPS（只看戰鬥循環會判毀滅），故本條是「隨機性優先」的判例，由維護者 2026-09-21 定案。
- 註：2025-10-26 起以「所有屬性統一歸毀滅」佔位，直到本日改判。

### 記憶（drone）的預設與例外

- **預設（drone 就是招牌）**：香菱（鍋巴）、菲謝爾（奧茲）、千織（人偶）、夢見月瑞希、愛可菲、愛諾、桑多涅（傀儡）、奧黛塔（獨舞倒影）。
- **例外（drone 只是載體，機制主軸在別處）**：
  - 芙寧娜 → 歡愉（沙龍成員；主軸是全隊資源轉全隊增益＋演出主題）。
  - 阿羅夏 → 同諧（圖加林除撕咬外還會為當前場上角色回血，且整套 kit 圍繞星超導反應傷害增益）。
  - 沃雅妮莎 → 同諧（喚春角笛除攻擊外還掛水／冰減抗，本身又是治療＋抗打斷＋領唱／重唱增傷的輔助）。
- **不視為 drone 的場上造物／協同攻擊**（現行判法：它們是技能效果或領域，不是隨行夥伴）：八重神子（殺生櫻）、雷電將軍（諸願百眼之輪）、珊瑚宮心海（化海月）、久岐忍（越祓雷草之輪）、阿貝多（陽華）、卡齊娜（沖天轉轉）、夜蘭（玄擲玲瓏）。若日後要把規則擴及這批，它們是第一批候選。
- **星鐵側的參照（旁證，非判準）**：星鐵的記憶命途與**憶靈系統**綁定——本檔抽驗的記憶角色全部掛有憶靈（`servant`）欄位：Trailblazer（迷迷）、Aglaea（衣匠）、Castorice（死龍•玻呂刻斯）、Hyacine（小伊卡）、Evernight（長夜）、Cyrene（德謬歌）、Robin • Summeretto（晴空樂手）。相對地，帶隨行召喚物而不在記憶的角色此欄為空：Lingsha 的【浮元】、Dan Heng • Permansor Terrae 的【龍靈】（後者 2025-10-11 實裝，已在記憶上線之後）。故 **Hyacine 不是「治療＋召喚物 → 記憶」的先例**——她的記憶來自憶靈系統本身；本節「drone 只是載體」的例外仍依原神側判準定案。

## 6. 新增或調整角色的流程

1. 取得角色資料（例：`https://gi.yatta.moe/api/v2/chs/avatar/<avatarID>`，或本機 AnimeGameData／EnkaDB 產物）。
2. 依第 3 節判準決定命途；在 `GenshinLifePathMap.json` 的 ID 遞增位置插入條目。
3. 跑下方驗證；有疑慮時再核 `LifePath.swift` 的解碼語意。
4. 在 `EndUserPublicDocs/ReleaseNotesArchive/` 當期 Release Notes 記錄對應關係，沿用既有句式，例如：「新角色（及其命途）：沃雅妮莎（同諧）、薇斯納（毀滅）」。
5. 若產生新判例，補記到第 5 節。

### 驗證

```bash
cd PizzaHelperUnited
python3 - <<'PY'
import json
p = 'Packages/EnkaKit/Sources/EnkaKit/Assets/GenshinLifePathMap.json'
d = json.load(open(p))
valid = {"Destruction", "Hunt", "Erudition", "Harmony", "Nihility",
         "Preservation", "Abundance", "Remembrance", "Elation"}
assert all(x['path'] in valid for x in d), "出現非法 path 字串"
ids = [int(x['id'].split('-')[0]) for x in d]
assert ids == sorted(ids), "ID 未按遞增排序"
assert len({x['id'] for x in d}) == len(d), "有重複 ID"
print(len(d), "entries OK")
PY
```

Swift 端的行為（case 名稱比對、`guessPath` 的 14／12／8 碼回退）定義在
`Packages/EnkaKit/Sources/EnkaKit/EnkaKitBackend/SharedTypes/LifePath.swift`；需要端到端確認時，
可把該檔的 `GenshinLifePathRecord.init(from:)` 與 `guessPath(for:)` 逐字複製成一支小腳本、
餵實檔斷言預期值（`10000140`／`10000143` 即以此法驗證）。
